# UI 개편 원칙 — 마메드네·퀸잇 벤치마크 (2026-09-15)

> **가져오는 것은 "원칙과 구조"뿐. 색·로고·아이콘·일러스트·문구·픽셀은 옮기지 않는다.**
> 벤치마크: **마메드네**(구 카카오헤어샵·AI 헤어 시뮬+예약)에서 *헤어 서비스 화면 구조*, **퀸잇**(4050 여성 커머스)에서 *어른이 읽는 밀도·크기*.
> ⚠️ 리서치 한계: App Store/Play 스크린샷을 **이미지로 추출하진 못함**(WebFetch가 마크다운 변환) — 원칙은 ①문서화된 두 앱 UX 특성(검색·스토어 설명·리뷰) ②아래 강제 5060 기준 ③frontend-design 절제 원칙에 근거. 근거열은 "화면 유형 + 출처 성격"으로 표기.

## 강제 5060 UX 기본선 (원칙과 별개·무조건 적용)
본문 **17px 이상** · 보조 텍스트 **15px 미만 금지** · 터치 타깃 **56px 이상** · 한 화면 **주 행동 1개** · **하단 고정 CTA** · 진행 표시(n/8) 상시 · **뒤로가기 항상 좌상단** · 색 대비 **WCAG AA** · **아이콘 단독 금지(라벨 동반)** · 스크롤 0 첫 화면에 **"지금 뭘 하면 되는지"** 보임.

## 원칙 10 (근거 / 우리 적용 / 지금 어긋난 곳)

| # | 원칙 | 근거(화면유형·출처) | 우리 화면 적용 | 지금 어긋난 곳 |
|---|---|---|---|---|
| P1 | **한 화면 = 주 행동 1개.** 부차 행동은 아래로 밀거나 접는다 | 퀸잇: "화면당 1상품(타앱 6+)"·터치 스텝 최소 (목록/상세, 검색·기사) | 설문 1문항/화면 유지, 결과지 CTA 우선순위(저장>제품>공유>재진단) | 결과지에 저장·공유·재진단·문의·제품 버튼이 비슷한 위계로 나열 |
| P2 | **본문·버튼을 키운다.** 크기·대비로 가독 확보(굵기로 밀지 않음) | 퀸잇: 큰 글씨·큰 결제버튼 (입력/결제) | body 17px·CTA 56px·보조 15px | 토큰 body 16·aux 14 / 결과지 일부 11~13px 문구 / 버튼 높이 제각각 |
| P3 | **낮은 밀도.** 카드 하나에 한 개념, 여백을 크게 | 퀸잇: "한 화면에 요소 적게" (목록/홈) | SectionCard로 블록 분리·여백 sec-2/3 | 결과지·홈 정보 밀집, 카드 경계 흐릿 |
| P4 | **입력 → 전/후 결과 → 다음 행동**의 3단 흐름 | 마메드네: 사진 1장→전/후 확인→바로 예약 (입력/결과) | 셀카+설문 → 결과지 Before/After → 제품·문의 (선공개 구조 = 이미 정합) | (구조는 정합) 시각적으로 전/후 대비·다음 행동이 약하게 보임 |

| P7 | **뒤로가기 항상 좌상단·아이콘+라벨.** 길 잃지 않게 | 5060 기본선(아이콘 단독 금지) | AppHeader(뒤로+제목+우측 1개) 공통화 | 일부 화면 뒤로 없음/아이콘만 |
